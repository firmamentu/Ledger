> 本文规定开发如何推进：阶段门禁、git、devlog、验证、质量规则。执行标准，不是建议。

## 2. git 规范

- 提交信息：**中文 + 类型前缀**（feat/fix/docs/chore/refactor/test），如 `fix: 用 flock 修复单实例竞态`；正文简要说明「为什么」。
- 每条提交结尾带署名行：`Co-Authored-By: Claude Code <noreply@anthropic.com>`。
- 提交粒度 = 一个可回溯的完整小步；自检通过才提交。
- 分支策略：main 线性提交（单人项目）；实验性大改才开分支，完成后合并回 main。
- 不提交构建产物（`.build/`、`build/` 已入 .gitignore）。

## 3. devlog 规范

- 每天一个文件 `devlog/YYYY-MM-DD.md`，固定两节：`## 完成` / `## 待办`。
- 每次会话开始读当天文件，会话结束前更新（由 CLAUDE.md 工作规则保证，无 hook）。
- 必须记录：当天完成事项、规格未覆盖处的**推断**（§0）、自检结果、待办与下一阶段。
- 语言：中文。

## 4. 验证规范（每阶段自检必做）

| 检查 | 命令/方法 |
|---|---|
| 构建（Xcode 工具链） | `./scripts/build-app.sh` + `codesign --verify` |
| 数据库冒烟 | `scripts/smoke-db.sh`（schema + 迁移幂等） |
| 单实例回归 | 同时启动两实例 ×5 → 恰存活 1；顺序重复启动 → 后者退出 |
| 零网络 | `lsof -a -p <pid> -i` 无输出 |
| 资源 | 空闲 CPU < 1%、RSS < 100MB（§16.7） |
| 验收对照 | 对照 docs/01-requirements.md §16 逐条打勾，记录进验收记录 |

## 5. 质量规则

- 阶段完成后可用 `/ponytail-review` 评审；发现问题先修再提交，修复必须回归验证。
- 规格未覆盖处：按 §0 最小合理推断 + 记入 devlog；「必须/禁止」条款不可放宽。
- 铁律：① 记账先于清理；② 知情先于行动；③ 本机先于一切。
- 硬约束（§2）：观察模式零写入、删除动作唯一 = 移入废纸篓、零联网、不强制权限、每条信息带 evidence、无 LLM、原生 SwiftUI。
- 新逻辑必须带最小验证（测试或可重复的自检命令），验证通过才算完成。

## 6. 交付物清单（§19）
